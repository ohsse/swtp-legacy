0한 줄 요약

판단은 Python 이, 결정·송신·이력은 Java 가, 승인은 사람이 한다. Python 은 5분마다 TB_CTRL_CMD_RST 에 판단 한 행을 쓴다. 벤더 계약은 한 줄이다. PUMP_CMD_YN / NATIONAL_CMD_YN 이 Y 이면 PUMP_TGT_HZ / NATIONAL_TGT_OPEN 값을 제어값으로 보낸다. Java 는 그 행을 모드에 따라 바로 보내거나(운전), 승인을 기다리거나(추천), 보내지 않는다(분석). 결과는 같은 행의 상태 컬럼에 되돌려 쓴다.

  • 장치는 둘이다. 송수펌프(주파수 Hz)와 국가산단 분기밸브(개도 %). 최종본에서 지방산단 밸브는 빠졌다. 두 장치는 같은 사이클에 동시에 명령을 받을 수 있다. (2026-09-30 드롭에서 지방산단 밸브가 나운 고수위 최종 fallback 으로 부활해 장치는 셋이 됐다. docs/gunsan-ctrl-5min-drop-review.md)
  • 펌프 기동·정지 판단은 없다. 운전 중 펌프의 평균 주파수를 정상 ±1 Hz, 위험수위 ±2 Hz 조정할 뿐이다. PUMP_COMB 는 "지금 도는 조합" 정보값이다.
  • Python 은 "제어했나"를 CMD_YN 으로 판단한다. 제어 직후 5분은 상태와 무관하게 쉰다. 상태 READY/APPLIED 는 반응 확인의 기준 명령을 고를 때만 쓴다. 그래서 Java 가 보내지 않은 명령을 REJECTED 로 되돌려 써야 반응 확인이 틀리지 않는다.
  • 제어 태그는 DB 에서 읽는다. 현장에서 태그를 확인해 SQL 로 넣는 순간 동작한다. 태그가 비어 있으면 송신하지 않고 사유를 남긴다.

25분 주기 타임라인

최종본은 "제어 → 5분 쉼 → 같은 방향이면 다시 제어" 시퀀스다. 정상일 때 같은 장치의 제어 간격은 최소 10분이고, 위험수위면 시퀀스를 건너뛰고 즉시 제어한다. 아래는 AI운전 모드에서 펌프 명령이 두 번 나가는 가장 짧은 경로다.

13:28 판부터 "제어했다"는 APPLIED 만 뜻한다. Python 은 직전 행 상태가 APPLIED 일 때만 다음 5분을 HOLD 한다(row_has_applied_command, main_5min.py:706-718, 943-946). 그래서 Java 는 다음 5분 판단 전에 송신을 끝내고 APPLIED 를 써야 한다. 늦으면 Python 은 제어가 없었던 것으로 보고 새 명령을 내 이중 제어가 된다.
시간 제약: 한 판단의 대기열 행 수 × 송신 주기(pumpTask 1분) + 판정 지연(≤30초) < 5분. 펌프 4대면 약 :04:15 로 들어가고, 여기에 밸브 행이 붙으면 넘친다. 밸브 행 수는 현장 조사 뒤 확정하며, 그때 이 식으로 송신 주기를 다시 정한다(2026-09-23 결정: 지금은 1분 유지).

4.4 장치별 검사 순서

  1. 현재값 — 펌프는 운전 중 펌프와 평균 Hz(PUMP_STATE_CHECK), 밸브는 개도(NATIONAL_DATA_CHECK).
  2. 현재값이 제어 범위 안인가 — 35~50 Hz, 국가 20~95 %. 밖이면 *_RANGE_CHECK.
  3. 정수지 여유 (펌프만) — CLEARWELL_LOW / CLEARWELL_HIGH.
  4. 시퀀스 — 위험이면 통과. 아니면 직전 5분 명령이 APPLIED 이거나 마지막 APPLIED 명령이 10분 안이면 *_POST_CONTROL_HOLD, 저장 방향과 다르면 *_DIRECTION_CHANGED. 걸리면 현재 방향을 *_WAIT_* 로 저장.
  5. 반응 확인 (위험 아닐 때, 같은 방향 연속일 때) — 효과 없으면 *_NO_RESPONSE, 판단 불가면 *_RESPONSE_CHECK.
  6. 스텝 적용 — 펌프 정상 1 Hz / 위험 2 Hz, 밸브 5%p. 클램프 후 변화 0.5 미만이면 *_LIMIT.

4.5 결과 행

장치별로 CMD_YN · CMD_STATUS · CUR · TGT · OBSERVE_UNTIL 이 실린다. 명령이 있으면 OBSERVE_UNTIL = CTRL_TS + 10분. REASON_CODE 는 | 로 이어지며 *_WAIT_* 토큰은 맨 앞에 붙는다(100자 절단). 지방산단 컬럼은 INSERT 에서 빠져 DDL 기본값(N / NO_COMMAND)으로 남는다. (2026-09-30 드롭부터 LOCAL_* 5컬럼도 INSERT 한다. 컬럼이 없으면 INSERT 자체가 실패한다.)

6제어 판단 게이트 — 소비자가 순서대로 묻는 것

트리거는 벤더 계약대로 *_CMD_YN='Y' 이다. 상태 READY 는 "아직 우리가 처리하지 않았다"는 표시로만 쓴다. 게이트는 싼 검사부터 놓는다. 오른쪽은 걸렸을 때 되돌려 쓰는 상태다.

  1. 트리거와 소유권
    *_CMD_YN='Y' 이고 *_CMD_STATUS='READY' 이며 대기열에 OPT_IDX=CTRL:<id>:<장치> 가 없는 장치. SELECT … FOR UPDATE 로 잠그고 다시 읽는다. 승인·소비자·만료가 같은 행을 다투는 것을 막는다.
    아니면 건너뜀
  2. 모드
    2 면 즉시 거절. 1 이면 나머지 게이트를 모두 통과한 경우에만 승인 대기로 남긴다. 승인 순간에 전체를 다시 돈다. 화면 폴링용 사전검사는 원시데이터를 읽는 운전 펌프 확인만 건너뛴다.
    REJECTED ANALYZE_MODE
  3. 테스트모드·제어테스트모드
    기존 checkTestMode()·checkCtrTestMode(). 꺼져 있으면 pumpTask 도 발행하지 않는다.
    REJECTED TESTMODE_OFF
  4. 신선도 (판단 마감)
    now − CTRL_TS ≥ 5분 − 20초(cycle-min·decision-close-sec)이거나 같은 장치에 더 새로운 CMD_YN='Y' 행이 있으면 마감된 명령이다. 두 시각 모두 같은 서버의 DB NOW()·Python 시계라 어긋나지 않는다(같은 Linux 호스트의 컨테이너).
    추천 모드 REJECTED APPROVE_TIMEOUT
    그 밖 EXPIRED STALE
  5. 대기열 비어 있음
    다른 명령의 FLAG 0/1 이 있으면 이번엔 적재하지 않고 READY 로 둔다. 다음 :40 재시도. 신선도가 먼저 끝나면 4번에서 만료.
    다음 사이클 재시도
  6. 값 범위
    펌프 PUMP_TGT_HZ 35~50 이고 기존 발행 조건 ≥ 25. 밸브 NATIONAL_TGT_OPEN 0~100. 정수로 반올림해 보내고 원값은 TRACE 에 남긴다.
    REJECTED OUT_OF_RANGE
  7. 태그 설정
    펌프는 운전 중 펌프 모두 CTR_AUTO_FREQ_TAG 가 있어야 한다. 밸브는 CtrlCmdTag 의 NATIONAL_OPEN 과 방향별 펄스 행(상향 NATIONAL_PULSE, 하향 NATIONAL_CLOSE_PULSE) TAG 컬럼이 채워져 있어야 한다.
    REJECTED TAG_NOT_CONFIGURED + 알람(시간당 1회)
  8. 운전 펌프 일치 (펌프만)
    원시데이터 PMB 4개로 지금 도는 펌프를 다시 읽어 PUMP_COMB 와 비교. 다르면 판단 전제가 바뀐 것이다.
    REJECTED PUMP_STATE_CHANGED
한 행에 펌프와 밸브가 둘 다 Y 일 수 있다. 게이트는 장치별로 따로 돈다. 펌프는 적재되고 밸브는 태그 미설정으로 거절되는 식의 결과가 정상이다. 대기열은 한 번에 한 행이므로 적재 순서는 펌프 먼저, 밸브 다음으로 고정한다.

7송신 — 펌프와 밸브는 보내는 방법이 다르다

펌프 주파수 설정 — PUMP_TGT_HZ

목표는 "운전 중 펌프의 평균 Hz". 운전 중인 펌프 각각의 CTR_AUTO_FREQ_TAG 에 같은 값을 보낸다. 조합이 1,3 이면 FREQ 행 2개.

  1. :40ANLY_CD='FREQ', VALUE=round(PUMP_TGT_HZ), OPT_IDX=CTRL:<id>:PUMP 행 적재
  2. :01:00pumpTask → sendCtrFreqTagItem. Kafka 송신, LOG 기록, FLAG=1
  3. +10초FLAG=2. 기존 코드는 주파수를 "전송 즉시 완료"로 본다
  4. :02:00두 번째 펌프 행이 같은 방식으로 나간다. 펌프 N대는 N분
  5. 묶음 완료같은 OPT_IDX 가 전부 FLAG=2 → APPLIED. 하나라도 3 → FAILED
스텝이 최대 2 Hz 라 기존 3 Hz 램프(PumpService.java:2748-2810) 없이 1회 전송한다.

국가산단 개도 설정 + 펄스 — NATIONAL_TGT_OPEN

목표 개도 태그 하나와 방향별 펄스 태그 둘이다(2026-09-30 확정). 목표 개도를 쓰고, 목표 > 현재(NATIONAL_CUR_OPEN)이면 OPENC, 작으면 CLOSEC 접점을 1→0 펄스로 쳐서 밸브를 움직인다. 순서는 항상 개도값 → 펄스다.

  1. :40개도 설정 태그에 ANLY_CD='VOP', VALUE=round(NATIONAL_TGT_OPEN) → 상향이면 OPENC 태그에 ANLY_CD='VPL', 하향이면 CLOSEC 태그에 ANLY_CD='VPC', VALUE=1. 현재 개도가 없으면 CUR_OPEN_UNKNOWN, 같으면 NO_CHANGE 로 REJECTED
  2. 다음 분VOP 송신 1회, 10초 후 FLAG=2 (FREQ 와 같은 방식, 신규 분기)
  3. 다음 분VPL/VPC 송신: sendCtrPulseTagItem 이 1 → 펄스 폭(3초) → 0 후 FLAG=2. 기존 sendCtrTagVVKItem 은 군산 경로에서 대기열 행을 FLAG=1 에 남겨(되돌리는 VVKStatusTask 가 부안 전용) 대기열 전체를 막으므로 쓰지 않는다
  4. 묶음 완료VOP·펄스 전부 FLAG=2 → APPLIED. 이때 POI-8601 개도 계측값을 TRACE 에 기록만 한다. 되읽기를 기다리면 다음 5분 판단보다 늦어질 수 있어서다(2장). 효과 확인은 Python response_ok_for_national_valve 가 유량·수위 추세로 한다
밸브 방식 확정(2026-09-30). 태그 3개, 개도값 → 방향별 펄스 순서(고정), 펄스 폭 3초(ctrl.cmd.valve.pulse-width-sec). 두 행은 1분 간격으로 나가므로(송신기가 한 번에 한 행), 간격이 문제면 송신 방식을 다시 본다.

8상태 전이 — 두 테이블의 상태가 어떻게 맞물리는가

8.1 판단 행 상태 (PUMP_CMD_STATUS / NATIONAL_CMD_STATUS)

상태쓰는 쪽뜻Python 다음 사이클
NO_COMMANDPython이 장치엔 명령 없음영향 없음
READYPython명령 생성. Java 가 아직 종결하지 않음제어 안 한 것으로 봄 → HOLD 없음
APPLIEDJava묶음 전부 FLAG 2(송신 완료)다음 5분 HOLD + 반응 확인 기준
REJECTEDJava보내지 않음. 분석모드·사용자 거절·추천 무응답 마감(APPROVE_TIMEOUT)·게이트제어 안 한 것으로 봄 → HOLD 없음
FAILEDJava보냈거나 보내려 했으나 송신 미완료(폐기·시간 초과)제어 안 한 것으로 봄 → HOLD 없음
EXPIREDJava운전 모드에서 마감(:04:40)까지 적재하지 못함(대기열 혼잡 등)제어 안 한 것으로 봄 → HOLD 없음
되돌려 쓰는 이유 (13:28 판). Python 은 APPLIED 만 "실제 제어"로 본다(main_5min.py:682-718, 주석 "실제 적용 성공 후 Java 제어부가 APPLIED로 변경해야 한다"). 쓰지 않으면 HOLD 가 한 번도 걸리지 않아 5분마다 명령이 나간다. APPLIED 이외의 종결 상태(REJECTED·FAILED·EXPIRED)는 Python 에게 모두 "제어 없음"이고, 처리 이유를 사람이 구분하기 위한 값이다(2026-09-23 유지 결정). FAILED 와 REJECTED 의 경계는 "SCADA 로 값이 나갔을 가능성"이다. FAILED 를 보면 현장 값을 확인해야 한다.

13미결 사항

  • 조합 변경의 주체 (P9). 소비자를 켜면 자동 조합 변경은 사라진다.
  • 추천 모드와 시퀀스의 어긋남. 무응답 명령은 다음 판단 20초 전에 REJECTED(APPROVE_TIMEOUT)로 마감한다. 승인 가능 시간은 약 4분 40초다. :04 이후 승인은 APPLIED 가 다음 판단보다 늦어 Python 이 새 추천을 낼 수 있다(다시 승인해야 나감). 벤더에 알려둘 사항이다.
  • 송신 시간 제약 (2장). 한 판단의 대기열 행 수 × 1분이 5분 판단 간격 안에 들어와야 한다. 밸브 행 수 확정 뒤 송신 주기를 다시 본다(지금은 1분 유지).
  • 되읽기 검증 없음. APPLIED 는 송신 완료 시점이다(FREQ 는 기존과 같고, 밸브도 13:28 판 대응으로 같게 했다). 게이트웨이 쓰기 허용(P6)이 없으면 APPLIED 여도 설비는 안 움직인다. 효과 확인은 Python 반응 확인이 맡는다.
  • 기존 10분 예측비교 팝업. 군산에서만 끈다($area 분기).

15현장 반영 절차

운전·추천·분석은 화면의 AI 운전모드(PumpStatus) 하나로 움직인다. 별도 켜기 스위치가 없으므로 배포 전에 AI 운전모드를 분석(2) 또는 추천(1)으로 둔다. 운전(0)인 채로 배포하면 다음 :40 에 펌프 주파수가 바로 나간다(펌프 쓰기 태그가 이미 있다). 배포 시 docs/sql/gunsan_ctrl_cmd.sql 1·2절을 실행하면 추적 테이블과 빈 밸브 태그 행이 생긴다. 밸브는 태그를 넣기 전까지 TAG_NOT_CONFIGURED 로 거절된다. ctrl.cmd.consumer.enabled=true 이면 모드와 무관하게 군산의 기존 조합 생성(pumpAiControlTask)은 쉰다.

15.1 확인

-- 펌프 주파수 쓰기 태그 (기존 컬럼)
SELECT PUMP_IDX, PUMP_NM, PMB_TAG, SPI_TAG, CTR_AUTO_FREQ_TAG, USE_YN
FROM   TB_CTR_PRF_PUMPMST_INF ORDER BY PUMP_IDX;

-- 기존 FREQ 송신 이력으로 태그 표기 형식 확인
SELECT TIME, TAG, VALUE, ANLY_CD, FLAG
FROM   TB_HMI_CTR_LOG WHERE ANLY_CD = 'FREQ' ORDER BY TIME DESC LIMIT 10;

-- AI 운전모드(PumpStatus: 0 AI / 1 추천 / 2 분석)·테스트모드·밸브 태그
SELECT FUNC_TYP, TAG_GRP, TAG, TAG_DSC, DEFAULT_VALUE
FROM   TB_WPP_TAG_CODE
WHERE  FUNC_TYP IN ('PumpStatus','TestMode','CtrTestMode','CtrlCmdTag');

15.2 입력

-- 펌프 태그가 비었거나 틀리면
UPDATE TB_CTR_PRF_PUMPMST_INF SET CTR_AUTO_FREQ_TAG = '<현장 확인 태그>' WHERE PUMP_IDX = 1;

-- 국가산단 밸브 태그는 TAG 컬럼에 (행은 배포 시 docs/sql 스크립트로 빈 값 생성됨)
UPDATE TB_WPP_TAG_CODE SET TAG = '891-365-POC-8603'
 WHERE FUNC_TYP = 'CtrlCmdTag' AND TAG_DSC = 'NATIONAL_OPEN';
UPDATE TB_WPP_TAG_CODE SET TAG = '891-365-VVK-8606'
 WHERE FUNC_TYP = 'CtrlCmdTag' AND TAG_DSC = 'NATIONAL_PULSE';
UPDATE TB_WPP_TAG_CODE SET TAG = '891-365-VVK-8607'
 WHERE FUNC_TYP = 'CtrlCmdTag' AND TAG_DSC = 'NATIONAL_CLOSE_PULSE';

-- 켜기·끄기는 SQL 이 아니라 화면의 AI 운전모드 토글로 한다 (PumpStatus)

15.3 켜는 순서

  1. 게이트웨이 쓰기 허용(P6)을 확인한다.
  2. 모드를 추천(1)으로 두고 승인 팝업이 뜨기를 기다린다.
  3. 펌프 1건 승인 → 대기열 FLAG 2, 판단 행 APPLIED, SCADA 화면의 주파수 설정값 변화를 확인한다.
  4. 밸브 1건 승인 → VOP·VPL 송신, POI-8601 이 목표로 움직이는지, APPLIED 인지 확인한다.
  5. 이상 없으면 운전(0)으로 전환한다.
  6. 멈출 때는 분석(2)으로 바꾼다. 전환 순간 대기열의 진행 중 명령은 기존 initCtrTag 로 폐기된다(5.1).
