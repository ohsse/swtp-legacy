# 군산 관망 조도계수 GA 보정 계획

군산 INP(절점 231 / 관로 229)를 대상으로 `roughness_ga_optimizer` 를 운영에 올리기 위한
**결정변수 그룹핑**과 **목적함수** 설계안이다.

`optimizer.py` / `groups.py` / `run_optimizer.py` 는 **수정하지 않는다.**
그룹은 INP `[TAGS]` 로만 주입한다(§2-4). 새 소스 파일도 추가하지 않는다.

- 대상 INP: 배수지 4곳(`나운(배)`, `오식도(배)공업`, `군장에너지`, `28`)을
  RESERVOIR → JUNCTION 으로 변경한 리비전
- 관측 매핑: `inpEditor/BE/editor/doc/sql/gunsan_inp_mapping_seed.sql`
  (압력 9점 / 수요 주입 5점)

---

## 1. 현황 진단

군산 INP 를 실제로 뜯어본 결과, 현재 설정 그대로 GA 를 돌리면 **보정이 사실상 일어나지 않는다.**
원인이 세 가지이고, 각각 독립적으로 작동한다.

### 1-1. 그룹핑 — 유전자 55개, 그런데 관로의 84%는 손도 대지 않는다

`groups.py:load_inp_tag_groups()` 는 INP `[TAGS]` 의 `LINK <id> <group>` 을 읽어
세 번째 토큰을 그룹명으로 쓴다. 그런데 군산 INP 의 `[TAGS]` 는 그룹 라벨이 아니라
**GIS 자산코드**다.

```
LINK  Bks-1715  1983000010:1201:31:01:00:WIIS.WATER_PIPELINE_LS:SAA030:
```

결과:

| 항목 | 값 |
| --- | ---: |
| LINK 태그가 붙은 관로 | 72 / 229본 |
| 그로부터 만들어지는 그룹 수 = 유전자 수 | **55개** |
| 그중 관로 1본짜리 그룹 | 41개 |
| 태그가 없어 `capture_original_roughness()` 에 잡히지 않는 관로 | **157본 / 연장 86 km (전체의 84%)** |

`capture_original_roughness()`(`optimizer.py:48-60`)는 `groups` 에 들어 있는 관로만 훑는다.
태그 없는 157본은 **C값이 영영 원래대로 고정**된다. 동시에 유전자는 55개인데 관측 압력은 9점뿐이라,
푸는 쪽은 심각하게 과소결정(under-determined)이다. 최적화가 안 되는 영역이 대부분이고,
되는 영역은 과적합된다.

> **[2026-09-04 개정] 배수지 절점화 리비전에서는 `[TAGS]` 가 통째로 비었다.**
> 자산코드마저 사라져, 이제는 과소결정 이전에 `groups.py:96` 이
> `ValueError: No LINK group tags found in INP [TAGS]` 를 던지며 **GA 가 즉시 종료**된다.
> 그룹핑은 개선 과제가 아니라 **실행 전제조건**이다.

### 1-1-2. 미관측 구간 — 관로의 절반은 압력 관측에 반응하지 않는다

수원 `B54` 에서 압력 관측 9점까지의 경로를 추출하면, **229본 중 108본 / 54,064 m
(연장의 52%)** 가 어떤 관측 경로에도 걸리지 않는다.

`[STATUS]` 에서 `군산(정)3` / `군산(정)4` 가 Closed 라 흐름 가능한 링크는 236개이고,
절점 236 대비 **독립 루프는 1개** — 사실상 순수 tree 다. 수요가 실측으로 고정된 tree 에서
관측점보다 하류에 있는 관로의 C값은 그 관측점 압력에 영향을 주지 못한다.

적합도는 압력 관측으로만 계산되므로, 이 관로들에 배정된 유전자는 **어떤 값을 넣어도 적합도가
같다.** 그룹 축을 정할 때 이 감도 구조를 무시하면 죽은 유전자가 생긴다(§2-2).

### 1-2. 탐색공간 — 유전자 값의 37~52%가 서로 구분되지 않는다

`apply_multipliers()`(`optimizer.py:63-81`)는 `clamp(원본C × 배율, roughness.low, roughness.high)` 다.
현재 설정(`config.*.json` 5개 파일 모두 동일):

```json
"multiplier": { "low": 0.4, "high": 2.0, "steps": 161 },
"roughness":  { "low": 60.0, "high": 160.0 }
```

군산 INP 의 원본 C값은 **100 / 110 / 130 세 종류뿐**이다. 그래서 배율 구간의 양 끝이
클램프에 눌려 **적합도 지형에서 완전히 평평한 고원**이 된다.

| 원본 C | 상한 포화 | 하한 포화 | 축퇴 비율 |
| ---: | --- | --- | ---: |
| 130 (62본) | 배율 > 1.2308 → 전부 160 | < 0.4615 → 전부 60 | **52%** |
| 110 (14본) | > 1.4545 | < 0.5455 | 43% |
| 100 (153본) | > 1.60 | < 0.60 | 37% |

GA 입장에서는 교차·돌연변이로 만든 자손의 절반가량이 부모와 **적합도가 완전히 동일**하다.
선택압이 걸리지 않아 세대를 낭비한다.

### 1-3. 목적함수 — 절대 RMSE 라 관말 오차가 묻힌다

현재 `objective_metric: "rmse"` 는 압력 절대오차의 RMSE 이고 부호만 뒤집어 적합도로 쓴다
(`optimizer.py:307-315`). 비교값은 `results.node["pressure"] × 0.1`(m → kgf/cm²)이다.

정수장 인근(`Bks-2496`)은 압력이 높아 같은 상대오차라도 절대오차가 크고,
관말(`옥석`, `최호장군`)은 압력이 낮아 절대오차가 작다.
결국 **정수장 근처를 맞추는 해가 선택되고 관말 오차는 방치**된다.
그런데 조도계수 보정에서 정작 중요한 건 누적 손실이 드러나는 관말 쪽이다.

## 2. 그룹핑 방안

### 2-1. 얼마나 나눠야 하는가 — 식별가능성이 상한을 정한다

Hazen-Williams 에서 절점 압력은 *수원 → 해당 절점 경로상 관로 손실의 합*이다.
따라서 GA 가 복원할 수 있는 그룹 수는 **관측이 만드는 독립 방정식 수**를 넘을 수 없다.

군산 망의 구조:

| 항목 | 값 |
| --- | ---: |
| 절점 | 236 (JUNCTION 235 + RESERVOIR 1) |
| 링크 | 239 (PIPE 229 + PUMP 4 + VALVE 6) |
| 흐름 가능한 링크 | 236 (`[STATUS]` Closed 인 `군산(정)3`·`군산(정)4`, Closed 관로 `Bks-1874` 제외) |
| 독립 루프 = 링크 − 절점 + 1 | **1개** |

즉 **사실상 tree 구조**다. 여기에 압력 관측 9점이 붙으면 이론상 방정식 9개지만,
관측점들이 상당 부분 같은 경로를 공유하므로 **실질 독립 정보는 5~7개**로 본다.

→ **유전자 수는 6~7개가 적정**하다. 55개는 물론이고 10개도 다소 많다.

### 2-2. C값을 그룹 축으로 쓰면 안 되는 이유 (개정)

이 문서는 원래 *"C값 = 관종·부설시기의 대리변수"* 를 전제로 C값 × 구경대 6그룹을 권장했다.
**그 전제는 이 데이터에서 성립하지 않는다.** 관로 주석의 준공년도와 교차한 결과:

| 원본 C | 본수 | 연도 확인 | 연도 분포 |
| ---: | ---: | ---: | --- |
| 100 | 153 | **0본** | 주석 자체가 없음 — 수기 추가 관로 |
| 110 | 14 | 13본 | 1990, 2001~2003 |
| 130 | 62 | 55본 | **1983~2003 (1983년만 17본)** |

1983년 관과 2003년 관이 똑같이 `C=130` 이다. 20년 차이에도 조도가 같다는 건 이 값이
실측·조사가 아니라 **입력 시 일괄 부여한 설계 기본값**이라는 뜻이다. C100 153본은 아예
이력 정보가 없는 수기 추가분이다.

따라서 C값으로 그룹을 나누면 관로 상태가 아니라 **데이터 출처로 나누는 셈**이 된다.

또한 그렇게 나눈 7그룹을 §1-1-2 의 감도 구조와 교차하면 **2개가 죽은 유전자**다.

| 구 권장안 그룹 | 본수 | 연장 | 관측반응 연장 |
| --- | ---: | ---: | ---: |
| `C100_D900-1100` | 65 | 40,136 m | 23,394 m |
| `C100_D1200+` | 63 | 33,270 m | 10,772 m |
| `C100_D450-800` | 24 | 11,730 m | 8,374 m |
| `C130_D1200+` | 49 | 11,639 m | 4,264 m |
| `C110_D900-1100` | 12 | 2,108 m | 2,104 m |
| `C130_D900-1100` | 11 | 3,027 m | **1 m** |
| `ETC` | 5 | 1,074 m | **0 m** |

### 2-2-2. 채택 — 구경대 × 관측구간 5그룹

C값을 축에서 빼고, **구경대**(도면에서 온 값, 마찰손실 민감도)와 **관측구간**(식별가능성)을
결합한다. 관측구간은 수원 → 압력 관측 9점의 경로가 만드는 서명이고, 미관측 관로는 트리에서
상류로 거슬러 올라가 **처음 만나는 관측구간을 상속**한다(지선의 조도를 그 지선을 먹이는
간선과 같게 본다). 이 상속으로 229본 전량이 귀속되며 고립은 0이다.

| `[TAGS]` 태그명 | 본수 | 연장 | 관측반응 연장 | 구성 |
| --- | ---: | ---: | ---: | --- |
| `GWANMAL_D1100UNDER` | 86 | 44,371 m | 23,727 m | 관말·내초도·신관·옥석·최호장군 계열, D1100 이하 |
| `GWANMAL_D1200UP` | 55 | 27,634 m | 1,550 m | 같은 계열, D1200 이상 |
| `SANDAN` | 44 | 13,986 m | 9,081 m | 국가산단 + 개정 계열 |
| `DEOKAM` | 25 | 12,573 m | 10,145 m | 덕암 전용 구간 |
| `TRUNK` | 19 | 4,421 m | 4,418 m | 관측 6점 이상이 공유하는 수원 직후 간선 |
| **합계** | **229** | **102,984 m** | | **유전자 5개 · 전량 커버** |

- §2-1 의 적정 유전자 수(6~7)를 만족하고, **모든 그룹이 관측 감도를 갖는다.**
- 구경대 경계는 `D1200` 하나뿐이고, 세분은 연장이 가장 큰 `GWANMAL` 에만 적용한다.
  `D450-800` 4본(1,215 m)은 관측 감도가 0 이라 `GWANMAL_D1100UNDER` 로 흡수했다.
- **배율 방식을 유지하므로 미관측 108본도 반드시 그룹에 넣어야 한다.** 태그를 안 달면
  원본 C 로 고정되어 관망 절반이 미보정으로 남는다.

> ⚠ 배율 방식(`new_c = 원본C × 배율`)인 한 **원본 C 는 그룹 축에서 빼도 기준선으로 남는다.**
> `GWANMAL_D1200UP` 에 배율 0.9 가 나오면 결과는 원본 C 의 0.9 배이고, 원본에 근거가 없으면
> 결과에도 그만큼의 근거밖에 없다. 이 의존을 끊으려면 유전자를 **절대 C값**으로 바꿔야 하며
> (`apply_multipliers` / `gene_space` 분기 추가), 그건 별도 판단 사항이다.

### 2-3. 대안 비교

| 방식 | 유전자 | 장점 | 단점 | 판단 |
| --- | ---: | --- | --- | --- |
| 현행 `[TAGS]` | — | 코드 그대로 | **현 리비전은 비어 있어 즉시 실패** | ✗ |
| C값 3그룹 | 3 | 과적합 위험 거의 없음 | 구경별 손실 차이를 못 담고, C값 자체가 근거 없음(§2-2) | ✗ |
| C값 × 구경대 | 7 | 전 관로 커버, 설명하기 쉬움 | C값이 상태 정보가 아님. 죽은 유전자 2개 | ✗ (구 권장안) |
| **구경대 × 관측구간** | **5** | 전 관로 커버, 모든 유전자가 관측 감도 보유 | 구간 경계가 관측점 배치에 종속 | **채택** |
| 설치연도(태그 앞 4자리) | 6 | 노후도라는 물리적 근거 | 현 리비전은 자산코드가 사라져 연도 확인 불가 | ✗ |
| 관측경로 서명만 | 7 | 이론적 최적 (각 그룹 = 하나의 압력 증분) | 미관측 108본이 미보정으로 남음 | 절대 C값 전환 시 재검토 |

> 참고: `[TAGS]` 자산코드의 첫 4자리는 설치연도다(`1983000010` → 1983년).
> 72본의 분포는 1983~2012년으로, `groups.py:year_to_group()` 규칙에 그대로 맞출 수 있다.
> 다만 나머지 157본의 연도를 모르므로, GIS 대장에서 전량 확보되면 그때 1순위로 올릴 만하다.

### 2-4. 적용 방법 — `[TAGS]` 에 직접 기입

`run_optimizer.py:468-471` 의 기본 분기(`load_inp_tag_groups`)를 그대로 쓴다.
config 의 `pipe_year_csv` 키는 **넣지 않는다.**

```python
if config.get("pipe_year_csv"):
    groups = load_year_groups(config["pipe_year_csv"])
else:
    groups = load_inp_tag_groups(inp_path)   # ← 이 경로를 쓴다
```

`[TAGS]` 를 택한 이유는 **BE 가 이 섹션을 왕복 지원**하기 때문이다.
`NetworkAssembler.mergeTags()` 가 `LINK <id> <tag>` 를 링크 properties 의 `tag` 로 병합하고,
`InpComposer.tags()`(194–206행)가 저장 시 다시 `[TAGS]` 로 되돌린다. 따라서

- 그룹 정보가 **INP 리비전과 함께 버전 관리**된다 (CSV 는 컨테이너 마운트라 INP 와 따로 논다),
- 에디터 화면에서 관로 속성의 Tag 로 **열람·수정**할 수 있고,
- config 변경도, 컨테이너 재배포도 필요 없다.

**태그 산출 규칙** — 기준이 바뀌거나 다른 리비전에 다시 붙일 때는 이 규칙대로 계산한다.

1. 수원 `B54` 에서 **흐름 가능한 링크만으로** BFS 트리를 만든다.
   `[STATUS]` 가 Closed 인 링크(`군산(정)3` · `군산(정)4`)와 Closed 관로(`Bks-1874`)는 뺀다.
2. 압력 관측 9점 각각에 대해 수원까지 경로를 거슬러 올라가며, 경로에 걸린 관로에 그 관측점을
   기록한다 → 관로별 **관측 서명**.
3. 서명이 빈 관로(미관측)는 트리에서 상류로 올라가 **처음 만나는 관측 서명을 상속**한다.
4. 서명 → 관측구간
   - 관측점 **6개 이상** 공유 → `TRUNK`
   - 서명이 `{덕암}` 뿐 → `DEOKAM`
   - `국가산단` 포함 → `SANDAN`
   - 그 외 → `GWANMAL`
5. `GWANMAL` 만 구경으로 세분한다. `D >= 1200` → `_D1200UP`, 미만 → `_D1100UNDER`.
6. `[TAGS]` 에 `LINK <pipe_id> <group>` 229행을 쓴다.
   **다른 섹션·인코딩(CP949)·개행은 건드리지 않는다.**

적용 후 검증한 것 — `load_inp_tag_groups()` 로 그룹 5 / 관로 229 확인, 28개 섹션 중 `[TAGS]` 만
0→229행이고 나머지 27개 불변, `[PIPES]` 229행 원문 동일, BE `InpNetworkParsingTest` ·
`InpComposeWriteTest` 통과.

> ⚠ **태그명에 공백을 넣지 말 것.** 파이썬은 `parts[2]` 하나만 읽는데
> Java `NetworkAssembler.joinFrom(row, 2)` 는 3번째 토큰 이후를 이어붙여, 공백이 들어가면
> 양쪽 해석이 갈린다.
>
> ⚠ 태그는 객체당 하나뿐이라, 그룹명을 넣으면 **GIS 자산코드는 함께 담을 수 없다.**
> 현 리비전은 `[TAGS]` 가 비어 있어 충돌이 없지만, 나중에 자산코드를 복원하려면
> 그룹을 다른 곳(CSV 분기)으로 옮겨야 한다.

## 3. 목적함수 방안

### 3-1. 1순위 — 탐색범위 축소 (config 만 수정)

§1-2 의 축퇴를 없앤다. **그룹핑 개선보다 먼저 하는 것이 좋다.** 효과 확인이 독립적이기 때문이다.

```json
"multiplier": { "low": 0.70, "high": 1.25, "steps": 111 },
"roughness":  { "low": 60.0, "high": 165.0 }
```

검산:

| 원본 C | 배율 0.70 | 배율 1.25 | 클램프 [60,165] |
| ---: | ---: | ---: | --- |
| 100 | 70 | 125 | 미발생 |
| 110 | 77 | 137.5 | 미발생 |
| 130 | 91 | 162.5 | 미발생 |

- **전 구간 클램프 미발생** → 유전자 값 111개가 모두 서로 다른 적합도를 만든다.
- 간격 0.005 로 해상도가 오히려 2배가 된다 (현행 0.01).
- 물리적으로도 C 70~163 은 노후관~신설관 범위를 충분히 덮는다.

### 3-2. 유량 관측의 위치 — 목적함수보다 "진단"

배수지 4곳을 절점으로 바꾸면서 수원이 `B54` 하나만 남았다.
이제 **유량지정 경계 + 단일 수두기준**이라는 교정(calibration)의 정석 구성이 됐다.
관로 손실이 압력차에 직접 드러나므로 GA 신호가 살아난다 — 이 INP 변경 자체가 가장 큰 개선이다.

그런데 바로 그 이유로 **유량 관측의 정보량은 제한적**이다.
유출이 전부 실측으로 고정되고 독립 루프가 4개뿐이면, 대부분의 관로 유량은 C 와 거의 무관하게
질량보존만으로 결정된다. 유량 6점 중 C 에 실질적 감도가 있는 것은 루프에 걸린 구간
(국가산단 · 옥석 · 최호장군 쪽)뿐이다.

따라서 유량 오차의 1차 용도는 **모델 정합성 진단**이다.

> 수요를 실측으로 고정했는데도 해석 유량이 실측과 크게 다르다 → 그건 C 문제가 아니라
> **태그 매핑 오류 · 단위 불일치 · 누락 수요**다. C 를 아무리 흔들어도 안 맞는다.

`build_error_tables()`(`optimizer.py:481-532`)가 이미 전/후 유량 오차표를 만든다.
**GA 를 돌리기 전에 배율 1.0(baseline) 상태의 유량 오차표를 먼저 확인한다.**

### 3-3. 3순위 — 가중 목적함수 (관말 오차가 계속 남을 때만)

§3-1, §2 를 적용해도 관말 압력 오차가 남으면 그때 도입한다.

```
J = w_p · RMSE_p / P_ref  +  w_q · RMSE_q / Q_ref  +  α · mean_g( (m_g − 1)² )
fitness = −J
```

| 항 | 역할 | 권장값 |
| --- | --- | --- |
| `P_ref`, `Q_ref` | 관측값 평균으로 나눠 **무차원화**. §1-3 의 고압 지점 지배를 없앤다 | 관측 평균 |
| `w_p` | 압력 가중 | 1.0 |
| `w_q` | 유량 가중 — 루프 구간 식별성 보조. 낮게 둔다 | 0.3 |
| `α` | **정규화항**. "설계 C를 크게 벗어나려면 근거가 있어야 한다"는 물리적 사전지식 | 0.3 |

정규화항이 필요한 이유: 관측 15점 대비 유전자 7개여도, 경로를 공유하는 관측점들 때문에
국소적으로는 여전히 여러 배율 조합이 같은 압력을 만든다(비유일해). 배율이 1.0 에서
멀어지는 데 페널티를 주면 그중 **가장 보수적인 해**가 선택된다.

구현 시 위치: `objective_score()`(`optimizer.py:307-315`)에 `objective_metric: "weighted"`
분기를 **추가**. 기존 `rmse` / `r2` / `corr_r2` 는 그대로 두어 기본 동작을 바꾸지 않는다.

### 3-4. 부수 개선 (여유 있을 때)

- `_on_generation`(`optimizer.py:406-432`)이 세대마다 `evaluate_solution` /
  `r2_solution` / `corr_r2_solution` 을 각각 호출해 **전체 시뮬을 3회 더** 돌린다.
  `solution_pressure_arrays` 결과를 한 번 계산해 재사용하면 세대당 27→25회.
  `run()` 종료 시에도 같은 중복이 4회 있다(385-388행).
- 관측 태그가 `fallback_sec`(600초) 내에 없으면 그 지점이 **조용히** 빠진다.
  기대 관측 수(9)와 실제 수가 다르면 경고 로그를 남기는 편이 안전하다.
- `error_rate_pct` 계산이 `not measured` 를 쓴다(512, 528행).
  measured 가 `0.0` 일 때와 `None` 일 때가 같이 처리된다.

## 4. 단계별 실행 계획

각 단계마다 **baseline 대비 RMSE 개선폭을 기록**한다. 그래야 어느 조치가 효과를 냈는지 분리된다.

| 단계 | 내용 | 변경 범위 | 성공 기준 |
| --- | --- | --- | --- |
| **0** | 매핑 DML 적용 (`gunsan_inp_mapping_seed.sql`) | DB only | `inp_anal_mapping` PRESSURE 9 / FLOW 5 |
| **1** | baseline(배율 1.0) 1회 실행, 유량·압력 오차표 확인 | 없음 | `demand_override_nodes_not_found` 가 비어 있음. 유량 오차율이 상식적 범위 |
| **2** | `multiplier` 범위 축소 (§3-1) | `config.json` | 세대별 best RMSE 가 단조 감소. baseline 대비 개선 |
| **3** | `[TAGS]` 태그 적용 (§2-4) | INP 새 리비전 | 로그가 `roughness_groups=5 tagged_pipes=229` |
| **4** | 가중 목적함수 (§3-3) | `optimizer.py` 분기 추가 | 관말(옥석·최호장군) 오차율 개선 |

**단계 1 에서 유량 오차가 크면 2 로 넘어가지 말 것.** 매핑·단위 문제를 먼저 잡아야 한다.
